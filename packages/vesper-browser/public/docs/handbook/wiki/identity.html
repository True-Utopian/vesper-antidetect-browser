Browser 0.4.14 / Workbench 0.5.19

Native identity settings

Use qualified policies and understand their limits.

Select a qualified native kernel

The vesper engine uses a separately qualified native Chromium runtime. Stage, qualify and activate engines through Browser engines while profiles are stopped and automation ownership is released. Operators use packaged kernels; the Chromium source checkout is a developer build requirement. Keep upstream notices and never substitute an unqualified binary under an existing qualification record.

Hardware presets and privacy controls

The native and desktop-4/desktop-8 identity presets retain the kernel’s browser version, operating system, screen and GPU. Desktop presets pair native CPU and memory policies. Custom enables bounded individual overrides. Fingerprint webgl restricted hides debug vendor/renderer exposure; audio seeded changes completed offline audio deterministically; fonts restricted limits bounded installed font discovery. These settings require runtime proof from the selected kernel.

Qualification boundaries

These are measured privacy controls, not full arbitrary device personas. They do not qualify complete WebGPU identities, realtime/device audio, all font/media exposure, physical GPU behavior on every machine or browser-wide leak avoidance. Linux software rendering qualification is distinct from physical GPU testing. Unsupported settings must be rejected rather than silently applied through page scripts.
