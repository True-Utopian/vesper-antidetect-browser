# What Vesper still lacks

By true-utopian. Checked against official documentation on 10 October 2026. This compares advertised capabilities to the local source and measured Vesper checks, not vendor internals. Availability can vary by plan and platform.

| Gap | Documented reference | Vesper status |
| --- | --- | --- |
| Coherent native identity/masking across browser, OS, canvas, graphics, audio, fonts and workers | [Kameleo kernels](https://developer.kameleo.io/concepts/kernels/), [Dolphin setup](https://docs.dolphin-anty.com/en/getting-started/guidelines-for-setting-up-a-profile-dolphin-anty), [Multilogin fingerprint controls](https://multilogin.com/help/en_US/browser-profile-setup/profile-settings-fingerprint-section) | Native Chromium plus optional upstream Brave. Page environment controls exist; a Vesper masking engine and complete consistency qualification do not. This is the largest technical gap. |
| Firefox and mobile environments | [Kameleo fingerprint filtering](https://developer.kameleo.io/tutorials/filtering-fingerprints/) and [mobile emulation](https://developer.kameleo.io/tutorials/emulating-mobile-devices/); [Multilogin navigation](https://multilogin.com/help/en_US/start/navigating-multilogin-x) includes mobile/cloud-phone workflows | Chromium/Brave desktop only. Changing viewport is not a mobile browser/device implementation. |
| Extension installation and assignment | [Kameleo extensions](https://developer.kameleo.io/tutorials/install-browser-extensions/), [Multilogin tools](https://multilogin.com/help/en_US/start/navigating-multilogin-x), [Dolphin profile tools](https://docs.dolphin-anty.com/en/working-with-profiles) | No managed extension catalogue, per-profile assignment or version/permission UI. |
| Teams, permissions, shared folders and cloud profile sync | [Dolphin teamwork](https://docs.dolphin-anty.com/en/teamwork/teamwork-in-dolphin-anty), [Multilogin tools](https://multilogin.com/help/en_US/start/navigating-multilogin-x) | Local single administrator. Leases protect automation ownership, not separate user roles. Cloud sharing is intentionally outside the current local scope. |
| Broadcast live actions to several browsers | [Dolphin synchronizer](https://docs.dolphin-anty.com/en/working-with-profiles/profile-synchronizer-in-dolphin-anty) | No master/follower action synchronizer. Running separate flows is different. |
| Cookie collection helpers, richer profile history and global settings | [Dolphin profile tools](https://docs.dolphin-anty.com/en/working-with-profiles) | JSON cookie tools, archives and API journals exist. Cookie Robot/Smart Paste style helpers, a comprehensive profile-history screen and global preferences do not. |
| Editable reusable proxy inventory/templates and integrated proxy services | [Multilogin tools](https://multilogin.com/help/en_US/start/navigating-multilogin-x) | Browser edits per-profile connections. Workbench reads configured inventory and probes it; a complete inventory editor/assignment UI is missing. Proxies remain operator supplied. |
| Broader automation integrations and easier authoring | [Kameleo integrations/examples](https://developer.kameleo.io/reference/code-examples/), [Dolphin script builder](https://docs.dolphin-anty.com/en/script-builder/script-builder-dolphin-anty) | Public APIs, TypeScript/Python clients, CDP/Puppeteer, durable flows and elapsed schedules exist. Selenium and full framework qualification, a recorder, many ready-made visual actions and calendar cron/wakeup remain missing. |
| Product polish and release qualification | [Multilogin navigation/customization](https://multilogin.com/help/en_US/start/navigating-multilogin-x) | This UI pass adds named destinations, compact row actions, tabbed settings, readable reports, first-class flow/schedule pages and guidance. Dark mode, localization, configurable columns, a hosted updater and native Linux acceptance remain open. |

Vesper already implements local persistent profiles, proxy authentication, metadata/folders/tags, templates, duplication, archive import/export, reversible trash, bulk operations, cookies, environment reports, connected desktop apps, APIs, visual flow editing, encrypted schedules and signed offline update contracts. These are original implementations. Their existence does not establish equivalent masking quality, vendor superiority or comparative performance.

The current priority is usability, followed by reliable proxy/extension management and native environment research. Cloud/team features should be designed separately if the local-only scope changes. Private REA vendor evidence stays outside the public source; see the individual research reports for exact hashes and boundaries.
