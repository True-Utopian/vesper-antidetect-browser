# Vesper completion gates

By **true-utopian**. Updated 12 October 2026. Applications and private data remain local; public source is prepared separately.

Vesper is an incomplete product, not yet a qualified replacement for Kameleo, Multilogin or Dolphin Anty. Passing a feature test does not complete the product. There is no defensible overall completion percentage while the vendor research and requirements remain incomplete.

The actual installed pair is Browser **0.4.5** with Workbench **0.5.7** as an enabled native add-on. It launches real Chromium, shares a Browser-owned profile store, and has passed extension-enabled automation, catalog removal with retained storage, calendar scheduling and verified export/import. The latest upgrade verified a complete backup of 57,516 private files (756,837,117 bytes) and preserved every original private file except the intended add-on registry update. TypeScript and Python calendar clients passed against the installed loopback services. The custom kernel remains a separate compilation and qualification gate. Workbench source builds now use the [Node.js 26 baseline](../runtime-baseline.md).

## Current acceptance records

- Installed pair: `test-results/native-engine/installed-pair-qualification.json`.
- Local extension Browser/Workbench run: `test-results/extensions/local-pair-qualification.json`.
- Extension UI import/assignment/removal and viewport checks: `test-results/extensions/ui-qualification.json`, `catalog.png`, `profile-assignment.png`.
- Upstream Chromium/Brave context regression: `test-results/native-engine/qualification.json`. This explicitly does **not** qualify the custom kernel.
- Stock Chromium rejected as a native-kernel candidate: `test-results/native-kernel/stock-host-admission.json`.
- Native compilation and post-build gate: private `.workbench/kernel-toolchain` records. A waiting or failed record is not a passed gate.

The 12 October source suite passed **149 tests**: 24 Browser tests and 125 Workbench/root tests. One optional external PostgreSQL test was skipped. Packaged extension automation saved a 68,657-byte archive whose SHA-256 matched its recorded artifact; importing it into another profile retained extension storage. A detached Browser service retained its owned running profile after its desktop manager exited, then stopped cleanly. Stock Chromium failed the native gate at extension-worker startup (CPU 12 instead of 4); the failed candidate remained rejected. These tests do not qualify a custom native binary, Linux runtime or vendor parity.

## Repeatable release audit

From the Vesper Workbench source checkout, run `node scripts/release-gates.mjs` to collect the current local acceptance records into `test-results/release/gates.json`. `--require-complete` returns a failing exit code until every aggregate gate passes. The report separates the full named roadmap from source checks, packaged Windows checks, actual installed API/UI/Python checks, native compilation, 26 native unit executions, direct and copied-runtime proof, installed native integration, real Linux execution and current public-main CI.

Installed records must match the requested Browser and Workbench versions. A previous release, upstream/CDP qualification, a running build, a changed executable or component, and Linux package structure cannot satisfy their corresponding installed or native gates. Native compilation is checked against the current executable digest; copied component/resource inventory is rechecked. The Linux runtime gate requires a real Linux installation, sandbox and native-kernel report. Missing evidence leaves a gate pending. This audit complements the individual qualification scripts; it does not change profiles or activate a kernel.

Browser 0.4.4 and Workbench 0.5.6 passed the packaged Windows pair, extension catalog removal and source UI checks (table actions fit at 1280 and 1366 pixels; embedded and standalone Workbench use the same primary colors). The guarded actual-installed upgrade, extended API/TypeScript run, Python scheduling client and direct native desktop UI review also passed. The full source suite passed 155 tests: 26 Browser and 129 Workbench/root, including four release-audit regressions. One optional external PostgreSQL test was skipped. Additional test executions do not add roadmap features. The custom kernel and real Linux runtime remain unqualified.

Raw vendor analysis remains private. Public conclusions distinguish documentation, static inference and measured behavior. Performance superiority and detection bypass are not established by these tests.

The latest 0.4.5/0.5.7 installed acceptance passed nine extended API checks, seven reusable proxy-inventory checks, the Python calendar lifecycle and direct native desktop UI inspection. The saved Workbench proxy run exported a verified 65,285-byte archive. Original profile/inventory state was preserved apart from owned qualification fixtures. The [surface audit](../fingerprint-surface-audit.md) adds an upstream baseline across eight contexts; it does not qualify native masking. The latest full source check passed 164 tests (29 Browser, 135 Workbench/root), with zero failures and one optional external PostgreSQL test skipped. See the [new masking handoff research](masking-handoff-followup.md) for the observed vendor boundaries and unresolved native consumers.
